# 집필 기준

- 독자는 비개발자다. 용어보다 일상적인 장면과 업무 사례를 먼저 제시한다.
- 존댓말 설명체를 쓴다. 기술 이름은 한국어로 뜻을 설명한 뒤 영문·약어를 병기한다.
- 각 장은 장면 → 개념 → 흐름/비교표 → 사례 → 한계와 책임 → 실무 점검 순으로 전개한다.
- 표 셀은 짧게 쓰고 표 아래에 의미와 적용 방법을 문장으로 설명한다.
- 제품 발표, 공개 시범 운영, 제한된 조기 접근, 일반 이용을 구분한다.
- 2026년 11월 9일까지 확인된 사실과 2027년 예측을 문장 수준에서 구분한다.
- 출처는 공식 문서, 공식 발표, 표준화 단체 자료를 우선하며 주장 가까이에 링크한다.
- 이미지가 자체 제작 도식이면 캡션에 '자체 제작'이라고 표시한다. 외부 화면이면 원문 출처와 확인일을 단다.
- 책 전체에 걸쳐 작은 가상 사례 '다온상점'을 사용하되 실제 도입 사례처럼 쓰지 않는다.
- 판매자 관점과 구매자 관점을 균형 있게 다룬다. 특정 회사의 홍보 문구를 일반적 성과처럼 옮기지 않는다.
